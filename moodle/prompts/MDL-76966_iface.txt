Issue MDL-76966: Multipage pdf conversions using ghostscript fail on windows server

assign/feedback/editpdf convert pdfs to a set of pngs for use with pdf annotation.

This is done by an adhoc task which runs on assignment submission create/update

Our site doesn't (yet) use document conversion, so this task is only relevant when a student has submitted pdfs. We also only use ghostscript, not the poppler/pdftoppm application.

After upgrading, we found that multi page pdfs get converted to an equivalent number of pngs (as expected), but each with "error converting this page" message, rather than reflecting the submitted pdf.

Digging into the code, we located the issue 

l.687 of  \mod\assign\feedback\editpdf\classes\pdf.php

*$imagefilearg = \escapeshellarg($imagefile . '%d.png');*

%d for the ghostscript commandline adds a page number to the filename.

But on windows...[ https://www.php.net/manual/en/function.escapeshellarg.php|https://www.php.net/manual/en/function.escapeshellarg.php]

"On Windows, *escapeshellarg()* instead{color:#de350b} *replaces percent signs,*{color} exclamation marks (delayed variable substitution) and double quotes *{color:#de350b}with spaces{color}* and adds double quotes around the string. Furthermore, each streak of consecutive backslashes ({{{}\{}}}) is escaped by one additional backslash."

... and general hilarity ensues.

We just removed the escapeshellarg function and everything works; it's not clear to me that sanitization is necessary for variables set in code without user input.
