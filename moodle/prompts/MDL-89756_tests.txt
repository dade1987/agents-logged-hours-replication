Issue MDL-89756: Administration: Correct copy and link scheme on the Notifications page

h2. Problem statement

MDL-89290 introduced the "From Moodle" CTA cards and reordered severity notices on the site administration Notifications page (/admin/index.php). Following review by the content team, several pieces of card copy need correcting and the outbound tracking/link scheme for the external CTAs needs to be aligned to the marketing team's current UTM convention. This ticket captures those copy and link corrections only; no layout, ordering, or structural changes are required.

h2. Current behaviour

On /admin/index.php, the "From Moodle" CTA cards currently show:

* Marketplace card: body text "Discover trusted plugins and integrations built for Moodle" (no product qualifier, no full stop); tick bullets without full stops.
* MoodleCloud card: tick bullets without full stops.
* Certified Moodle Partners card: titled "Certified Moodle Partners"; body text "Work with a Moodle Certified Service Provider near you for hosting, upgrades, integrations or custom development."; button labelled "Find a Partner"; links to https://moodle.com/services/certified-service-providers/; tick bullets without full stops.
* Feedback survey card: body text ends "...Turning it on takes one setting."; tick bullets without full stops.

The three external CTA links (Marketplace, MoodleCloud, Partners) are built by {{notification_ctas::build_tracked_cta_url()}} with {{utm_source=moodle_admin}} and {{utm_campaign=<cta key>}} (for example {{utm_campaign=marketplace}}), alongside the existing base64-encoded "site" parameter.

h2. Expected behaviour

h3. Copy changes ({{lang/en/admin.php}})

* {{notificationctamarketplacetick1}}: change to "1,500+ plugins, themes and integrations."

h3. Link changes ({{public/admin/classes/output/notification_ctas.php}})

The Partners CTA base URL changes from https://moodle.com/services/certified-service-providers/ to https://moodle.com/get-moodle/. Only the root URL changes; the existing base64 "site" parameter and the utm parameters below continue to be appended the same way as for the other two external CTAs.

The UTM parameters appended by {{build_tracked_cta_url()}} for all three external CTAs (Marketplace, MoodleCloud, Partners) change from the current {{utm_source=moodle_admin}} / {{utm_campaign=<cta key>}} pair to:

* {{utm_source}} = the site's own hostname (host part of {{$CFG->wwwroot}})
* {{utm_medium}} = {{lms_referral}}
* {{utm_campaign}} = {{000_lms_cta}} (fixed value, the same for all three CTAs)
* {{utm_content}} = the CTA key ({{marketplace}}, {{moodlecloud}}, or {{partners}}), replacing the identifying role previously played by {{utm_campaign}}

The existing base64-encoded "site" parameter (fullname, wwwroot, major version) is unchanged and continues to be appended alongside the new utm parameters. The feedback survey CTA remains an internal link with no query parameters, unchanged.

h2. Value

* Corrected, brand-accurate copy avoids referring to "Moodle" (the organisation) as something a site can be "hosted by" in a confusing way, uses consistent product naming (Moodle LMS) where appropriate, and gives more customer-friendly framing for the feedback survey prompt.
* Full stops on all CTA card bullet points meet the content team's accessibility guidance for bulleted lists (screen readers announce list items more clearly as complete sentences).
* The reworked UTM scheme ({{utm_source}}/{{utm_medium}}/{{utm_campaign}}/{{utm_content}}) aligns the Notifications page CTAs with Moodle HQ's marketing team's standard tracking convention (source = where, medium = how, campaign = what), replacing an ad hoc scheme that was inconsistent with links used elsewhere on moodle.com properties.
* Renaming the Partners card to "Moodle Services" and pointing it at the general https://moodle.com/get-moodle/ landing page matches how Moodle HQ consistently drives this kind of CTA traffic on other properties, per the content team's review.
