Issue MDL-88644: Draft → draft file copy corrupts files.source metadata

h2. Problem

The {{file_save_draft_area_files}} function unwraps draft file *files.source* metadata to the plain source filename even when the destination file area is also a draft.

That’s correct when saving draft files into a final file area, but it’s wrong when resuming an autosave  where files are copied from one draft area to another draft area.

h2. Issue

When calling {{file_save_draft_area_files($sourcedraftid, $usercontext->id, 'user', 'draft', $destinationdraftid);}}

h3. Expected result

The destination draft file keeps serialised draft metadata in *files.source*, e.g., a serialized stdClass containing source and original.

h3. Actual result

The destination draft file gets set to the *plain file name*. This later causes paths that expect draft *files.source* metadata to call something like {{unserialize_object('driverslicense.jpg')}}which results in notices like  {{unserialize(): Error at offset 0 of 11 bytes}}.

This appears related to [https://moodle.atlassian.net/browse/MDL-87353|https://moodle.atlassian.net/browse/MDL-87353|smart-link], but that issue seems to have fixed the unsafe unserialisation issue without preserving draft source metadata during draft → draft copies.

h2. Replication

The issue can be replicated with a PHPUnit test in *lib/tests/filelib_test.php*
