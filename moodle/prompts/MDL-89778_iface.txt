Issue MDL-89778: Async course deletion puts the course in the category recycle bin twice

Deleting a course with *Delete courses asynchronously* enabled creates *two* identical entries in the category recycle bin instead of one. One copy is made when the manager clicks Delete, and another when cron runs the deletion task.

h3. Steps to reproduce

# Enable _Site administration > Courses > Delete course > Delete courses asynchronously_.
# Enable _Site administration > Plugins > Admin tools > Recycle bin > Enable category recycle bin_.
# Create a course, then delete it.
# Open the category recycle bin — one entry (correct so far).
# Run cron.
# Open the category recycle bin again.

*Expected:* one entry.

*Actual:* two identical entries:

!image-1789013410438.png|width=417,alt="image-1789013410438.png"!

h3. Why it happens

{{delete_course()}} runs the {{pre_course_delete}} plugin callbacks at {{lib/moodlelib.php:4493}}, which is *before* the async early exit at line 4512. So {{tool_recyclebin_pre_course_delete()}} takes a backup, then the course is queued and the function returns. Cron later runs {{course_async_deletion}}, which calls {{delete_course()}} again — the callbacks run a second time and take a second backup.

h3. Same cause, other effects

* The {{before_course_deleted}} hook is dispatched twice, which will affect third-party plugins.
* Each copy is a full course backup including user files, so a large course is backed up twice: double the cron time and double the moodledata usage.
* Restoring one entry leaves the other behind, so the course can be restored twice.

h3. Suggested fix

Move the {{pre_course_delete}} callbacks and the {{before_course_deleted}} dispatch to *after* the async early exit, so they run only on the path that actually deletes. Keep {{action_course_mark_for_deletioninprogress()}} before it — that is what shows "Queued for deletion".

*Decision needed:* this changes _when_ the recycle bin copy is taken (cron time rather than click time). [MDLQA-21990|https://moodle.atlassian.net/browse/MDLQA-21990] step 3 currently expects the entry to exist before cron, so that test needs updating alongside the fix. The alternative is to keep the copy at click time and have the task skip the callbacks instead.

h3. Reproduction test

This test fails on current main with {{Failed asserting that 2 matches expected 1.}} and passes with the suggested fix. With the fix applied, {{tool_recyclebin_testsuite}} (37 tests) and {{courselib_test --filter delete_course}} (3 tests) still pass.

{code:php}// public/admin/tool/recyclebin/tests/async_course_deletion_test.php
namespace tool_recyclebin;

/**
 * @covers \tool_recyclebin\category_bin
 */
final class async_course_deletion_test extends \advanced_testcase {

    /**
     * A course deleted asynchronously must leave exactly one restorable copy in the category bin.
     */
    public function test_async_deletion_stores_a_single_item(): void {
        global $DB;

        $this->resetAfterTest();
        $this->setAdminUser();

        set_config('categorybinenable', 1, 'tool_recyclebin');
        set_config('enablecourseasyncdeletion', 1, 'moodlecourse');

        $course = $this->getDataGenerator()->create_course();
        $this->assertEquals(0, $DB->count_records('tool_recyclebin_category'));

        // A manager deletes the course. Async is preferred, so this only queues the ad hoc task.
        delete_course($course, false);
        $this->assertTrue($DB->record_exists('course', ['id' => $course->id]));

        // Cron runs the queued \core_course\task\course_async_deletion task. The task calls
        // delete_course() with $showfeedback = true, so swallow the progress output it prints.
        ob_start();
        $this->run_all_adhoc_tasks();
        ob_end_clean();

        // The course row is now really gone.
        $this->assertFalse($DB->record_exists('course', ['id' => $course->id]));

        // There must be exactly one restorable copy, whenever the backup was actually taken.
        $this->assertEquals(1, $DB->count_records('tool_recyclebin_category'));

        // And that copy must really restore.
        $recyclebin = new \tool_recyclebin\category_bin($course->category);
        $this->assertCount(1, $recyclebin->get_items());
    }
}{code}
